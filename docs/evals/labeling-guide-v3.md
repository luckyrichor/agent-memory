## 模型、版本与边界

沿用公开中文冻结模型对，模型名来自 `evidence_v3.MODELS`。此次只修改审核提示词与附带证据的响应结构；候选、主体、原始逐轮来源不改。独立新提示词 `prompts/labeling-guide-v3-evidence-v1.txt` 与过去的 `annotation-v3.txt` 不是同一版本。旧模型标签、旧词法过滤器、人工确认子集全部留历史，不拼接进新批次。

每条 keep 按候选语义拆出所有适用细节，逐项给出 `detail, source_id, quote`：主体、关系、程度、频率、数量、时间、诊断确定性。不存在的维度用空数组，主体和核心关系必须有证据。缺少任一具体细节的用户原话支持，整条 uncertain。具体判定要求直接见提示词；不得按期望保留数放宽。

## 精确程序校验

`evidence_v3.validate_quotes` 只验证格式与引用：

- 引用绑定当前候选本来的来源，source_id 必须唯一、存在且 role=user。
- 非空 quote 必须是该条用户 text 的连续精确子串，不做标点、空白、同义词等归一化。
- keep 的主体和关系证据数组非空；引用失败则最终 uncertain，保留模型原判与失败码。

程序不判断原话是否语义支持候选、不判断模型是否遗漏细节，也不以词串拼接替代语义判断。即使“喜欢”是“我不喜欢”的子串，引用检查仍可能通过；模型必须阅读完整上下文判断否定、第三人、问句、假设、助手先提、程度频率和日期事件绑定，最终仍依赖独立人工盲审。引用校验通过不是金标准证明。

## 离线试验冻结与泄漏说明

固定种子按 conversation_id 隔离，近半开发、近半最终验证，按原审核来源及人工标签平衡计数。划分仅使用条目/会话身份和计数，未以模型结果选择划分；清单、原始输入、提示词、程序 SHA 在首次调用前锁定。

本轮只锁定一个提示词版本，不利用最终集反复调参。输入仅为原始候选与来源及身份字段，不含人工标签/理由、旧模型标签、分类或参照。最终集只有开发阶段两模型均完成后才调用；一次最终评价结果保留，重启只回放已完成结果，不重复调用。失败台账默认禁止重试，需要明确恢复实施，不能删台账后当新实验。

这些题的人工标签此前已经存在，旧规则还用过原盲抽数据。本次最终集只是对新提示词开发隔离，并非历史从未暴露的独立基准。代码助手不把重新划分消除历史暴露当成事实。最终金标准采纳仍以新的未审样本为依据。

## 条件执行

`run-evidence-v3.py prepare/offline/report/full` 分别用于锁定、离线模型实验、只读核算、通过后整批重标。整批是完整冻结候选文件，不能只补旧模型未完成的尾部；两模型新标签都完整后才允许按原八列生成新盲审表，排除全部已人工审核项。新表的固定种子与标准由执行清单记录，未达到数量则如实失败、不凑表。

HTTP 失败立即保留私有原始响应与元数据台账，不自动替换模型、不充值或开通后付费。额度阻塞并不等同于模型质量不通过；不获得完整结果就不执行整批重标。补量继续依赖新盲审通过。

运行计数、划分数量、验证日志和当前阻塞见自动交接报告；不手工复制数字到本规程。
