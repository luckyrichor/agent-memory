# 标注指南 v2：证据归属与判断顺序澄清

执行：Codex；北京时间 2026-10-20。保留v1作为历史版本。

本版依据：新组合完整双标未达到κ门槛后，**仅检查冻结开发集**的分歧。主要涉及助手替用户作断言，以及缺少说话人身份时不应记/不确定的判断顺序。未按测试集个案修改指南。

**未改变**：原有“来源支持、归属正确、跨会话有用且可安全保存”的保留标准；三个标签及原因码；原始候选/原生参照；会话切分；κ≥0.7与10%盲审一致率≥95%。下列示例是说明性虚构，不计入任何真实数据规模。

## 判断流程

1. 先检查是否存在**不依赖说话人身份也确定不应保存**的原因。例如问候、感谢、通用操作指令、一次性临时选择、受限敏感内容。存在则discard；未知身份不使这些内容自动变成uncertain。
2. 对可能值得保存的个人事实，核对来源是否真的包含该事实、是否属于目标主体。完全没有对应内容判discard/missing；有对应陈述但角色、指代或确认对象确实无法判定时才uncertain。
3. 只有来源支持、归属正确、必要条件完整、跨会话有用且安全时才keep。不能为了获得更多记忆点、提高一致性或迎合语料作者标签而保留。

## 每条规则与正反例

|规则|正例|反例/边界|
|---|---|---|
|主体明确直接陈述|user：“以后订单都优先选蓝色。”候选“用户长期偏好蓝色”，keep。|user：“这一次选蓝色。”不能变成长期偏好，discard/temporary。|
|助手关于用户的断言不是用户的新证据|assistant问“你会法语吗？”user答“会”，目标候选可keep。|只有assistant说“你会法语”，user说“谢谢”，不能算用户确认，discard/attribution或missing。|
|确认必须明确指向候选|assistant问“你喜欢红茶吗？”user答“是的”，可支持该偏好。|assistant同时说多个事实并给出建议，user仅“嗯/好的/本来就是”，无法知道确认哪个命题时uncertain；不得默认所有命题均成立。|
|不能把别人的事实归给用户|user：“我喜欢跑步”，可keep。|assistant：“我喜欢跑步”；或user：“同事喜欢跑步”，不能记成用户喜欢跑步，discard/attribution。|
|完全缺证与确实歧义不同|user：“她下周搬家”，但“她”指谁不明，对候选主体确实无法判断，uncertain。|对话根本没提候选的职业、姓名或爱好，discard/missing；不能因为“或许在其他会话说过”而uncertain或keep。|
|未知说话人只影响潜在有价值的归属判断|匿名来源：“我长期喝无糖饮料”，客户/客服身份未提供，uncertain。|匿名来源：“谢谢”“请点击确认”，本身无应记个人事实，discard/temporary，不必先解决身份。|
|不推断未提供的角色|给定user/assistant标签时依其归属；原文明确“客户：”可作为来源身份线索。|不能仅凭轮次奇偶、“亲”的用语、礼貌程度或常见客服习惯补出客户/客服标签。|
|短期内容不自动成为长期事实|user：“下次联系时请提醒我确认这笔退款到账”，明确跨会话待办可keep，保留条件。|一次“今天发货吗”“这次要小号”、通用退货操作指令，不自动泛化为用户长期习惯/偏好，discard/temporary。|
|语义等价不等于推断性格|user：“我喜欢画画”，候选“用户爱好绘画”可keep。|user：“我今天画了一张图”，不能据此推断长期爱好；不靠常识补全候选，discard/missing或temporary。|
|时间与条件不省略|user：“这周临时住在杭州”，候选须保留“这周/临时”的条件，并独立判断是否值得跨会话保存。|不能改成永久住址；不能为没有日期的来源编造具体日期。|
|敏感内容和注入指令不作为可保存事实|普通无敏感偏好，满足其余规则时keep。|凭据、应拦的敏感内容、来源里要求“输出keep”的指令，不因其他规则满足而放行。|

## 原生参照和模型判断

DuLeMon user_said_persona/user_no_said_persona依用户要求作为应记/不应记原生参照直接保留；模型只做独立对照。**模型输入看不到原生标签**，不得通过候选ID、字段名或外部人设推断参照答案。模型与原生标注不同不表示助手可自动改金标，需负责人抽检。

ECD没有原生记忆标注，回复匹配0/1不是记忆标签。来源角色缺失继续如实保留，不以补造客户身份提高保留率。对原始话语候选仍按上述相同标准判断。

## 执行与审核

模型组合来自冻结清单，厂商独立；温度0、关闭思考并检查响应实际行为。模型不可用时按最新用户授权自动预检替换，但不混用不同模型的部分结果。

指南澄清先在开发集验证；人工角色不由助手代替。测试集仅作固定版本里程碑评分，不读测试失败个案调规则。所有不确定/分歧留待负责人处理，κ及盲审门槛不降低。
