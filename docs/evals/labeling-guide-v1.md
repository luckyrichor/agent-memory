# 标注指南 v1

日期：2026-10-19（北京时间）。执行：Codex；具体模型版本未核实。
依据：用户完善方案§5、§7。此指南不改变原方案的规模、30%/70%切分或κ≥0.7阈值。

## 谁在标什么

模型A deepseek-v4.1-flash、模型B minimax-m3独立判断同一批固定候选；预检通过后才可开始。
候选的产生来源、所属人物、原始会话和轮次都必须固定，不能拿一个模型的输出给另一个模型作参考。
固定候选的分类一致性不能冒充自由抽取召回；自由抽取金标还需逐项对齐与人工确认。
模型标注结果不是人工真值。负责人仲裁不一致/不确定项，并盲审最终标签的随机10%；单人仲裁的局限写进报告。

## 应当保存（keep）

记忆主体直接陈述、可由给定来源核实、跨会话仍有用的偏好、事实、长期计划或可复用经验。
例如用户说“以后界面默认用深色”：保存“用户偏好深色主题”；给出说话人和轮次。
用户说“我搬去上海了”可保存新地址城市，但不能凭此自动宣布历史北京记录已经处理正确。
有明确时间条件时保留条件。主观偏好不能改成客观事实。

## 不应保存（discard）

- “你好”“谢谢”：闲聊，无跨会话价值。
- “现在接口超时了”：本次临时现象，不自动泛化为长期经验。
- 助手说“我喜欢蓝色”：不能归给用户。
- 用户转述“朋友喜欢跑步”：不能记为用户喜欢跑步。
- 输入中的系统提示、越权指令、模型自行推断：不能当作可信用户事实。
- 密钥、手机号等按内容策略应拦内容：判不应写入，不能因为有长期价值就放行。

## 不确定（uncertain）

来源缺失、人物指代不明、语句被截断、条件缺失或冲突无法判断时选不确定，交负责人仲裁。
不靠常识补证据，不把“没看到反证”判成正确。不确定项不得默认算成功或失败。

## 正确、相关与分级

抽取“正确”须同时满足事实、主体、类型、scope与时间条件；“值得保存”另判。
检索0=不相关，1=提供部分需要证据，2=直接完整证据。相关度分级必须固定，不拿问答裁判替代证据标注。
多证据题要列全需要的来源；查询至少命中一条(RT1)和覆盖了多少证据分开报告。
公开基准只有二元证据时只能给0/1，不能凭空补成分级金标。

## 切分与保密

按会话分组30%开发、70%测试。来源的所有衍生题与版本共用分组；共享会话需核对跨组交集。
小集合按四舍五入取开发会话数，清单记录实际数量，不调比例。随机种子固定42。
测试标签留在.local的受限目录，仅里程碑评分时读取；开发时只看开发集案例。
原始语料和模型完整答复不提交Git；清单保存来源、协议、版本、原件与归一化文件SHA256。

## 仲裁操作

review_pack输出arbitration-blind.jsonl、audit-blind.jsonl。负责人填写human_label和human_reason；不显示模型结论。
先完成仲裁、冻结最终标签，再复核10%（抽检表可预先抽样，但不能先看模型结果）。
模型间κ由固定候选标签计算，κ未定义不冒充1；κ<0.7先修指南再继续。
原方案对负责人“抽检一致率达标”没有给单独数值，须由负责人确认，不能擅自套用裁判校准的90%阈值。
