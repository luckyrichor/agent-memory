## 审核交接

当前必填仅 dulemon-native-reference/audit-blind.csv（230条），与上一版冻结模板字节相同。其余 DuLeMon 模型对照和 PerLTQA 审核本轮暂缓；ECD 120段表已备好，不扩展本轮必填清单。全部人工字段空白，助手不代填。ECD、DuLeMon审核原文只放 .local/ 和负责人私聊附件；群里只发汇总报告。

ECD暂定负样本来自冻结模型共同舍弃，不标成已核验真值。人工小样从原400会话按种子42抽120段，先用第一人称与个人信息关键词分层，全部25段有线索、95段无线索。角色未知，所以“线索”不等于实际用户事实；是否应记及归属由负责人直接标记。分层清单/来源ID/原文只在私有包，公开仅数量、方法和哈希。原会话 dev/test 不重新分配。

人工回填后用 finalize-native-audit.py：验证冻结文件哈希、原始230抽样及回填完整性；直接与冻结原生标签计算一致率，再应用人工更正。低于95%时输出仅人工确认子集；不得沿用全部原生参照规模。当前未收到回填，人工金标仍未验收。

## 裁判池

完整评测按方案§7估算：题数×组数×重复数是判分次数，答题调用另计；不能把两者之和当判分次数。judge_budget 在代码中计算，报告列出参数。1000输入/100输出 token 是方案估算，不是账户实际余额；E4/CX5如单独调用还须另外预算，不把未计入的任务声称已覆盖。

先查官方采样控制、模型列表及实际调用，再做五次一致/100格式预检。接口不返回剩余额度时保留 unknown，不能从成功一次推断充足，不能根据推荐模型顺序冒充额度排名。402只证明所调用服务的免费包耗尽，不等于整个账号所有模型或付费余额为0。不充值、不开启后付费。TokenHub“启用管理”可查剩余免费额度，控制台数据到齐后 rank_judges 才允许冻结主裁判加至少两个合格备选。

run-judge-table.py 要求带查询日期和证据哈希的冻结池。持续失败最多三次、402立即切换；切换会从整表第一条重判，失败模型的部分分数只留私有尝试台账，不进入完成表。只有整表完成才原子发布 result.json；每条包含请求模型、response.model 与时间。不把未版本化服务ID当已核实权重版本。标注模型不走这个自动切换流程。

预检和自动切换测试都不能代替负责人裁判人工校准。当前不执行阶段2正式对比评测。
