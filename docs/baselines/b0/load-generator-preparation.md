# B0 独立压测机准备说明

范围：阶段2 PF1–PF10 的准备要求，尚未开始压测。方案原文保留；负责人新决定用独立 Linux 云服务器替代方案中的 Mac 发压端。

## 负责人准备与访问交付

- Linux x86_64 或 arm64，至少2 vCPU、2 GiB内存、10 GiB可用磁盘；按量计费、固定公网IP，地域与被测服务器不同。内存建议4 GiB，以避免发压工具自身受限。
- 提供地域、实例规格、公网IP、带宽上限和非root登录用户名。不要在聊天、报告、Git或命令参数中发送私钥、口令、令牌。
- 访问沿用服务器现有密钥管理渠道：将授权公钥加入临时机账号，私钥留在原有私有配置处；仅交付SSH主机别名/连接配置路径与公钥指纹。若需口令，由负责人用既有安全渠道配置，不发群。
- 被测机安全组与主机防火墙只对压测机固定公网IPv4 /32（IPv6则/128）开放本次专用HTTPS端口；不向0.0.0.0/0开放业务API、PostgreSQL、监控端口。SSH仅对执行端授权IP开放。
- 被测API采用隔离评测租户和短期JWT，令牌以临时机权限0600的私有文件注入进程，不放脚本、URL、报告或聊天。被测机数据库只绑定本机。
- 不提前修改安全组；拿到固定IP后再记录规则ID、端口、有效时间，压测结束后删除规则并实测公网不可访问，撤销临时令牌/访问权限。

## 工具与版本冻结

计划使用 Grafana k6 OSS v1.0.0（固定版本，非声称当前最新版），配 Linux procfs 1秒资源采样；无需JVM或浏览器。正式运行前核对官方发布包SHA256、`k6 version`及二进制SHA256，将实测写入环境指纹；此时尚未安装/验证临时机工具。

主负载用 `constant-arrival-rate` 开环执行器，每次迭代一个请求；记录计划/实际到达率、dropped_iterations、超时、错误率。VU不足和发压端饱和须单独报告，不能只对完成请求计算漂亮的长尾。闭环仅找最大吞吐。

依据：[固定到达率执行器](https://grafana.com/docs/k6/latest/using-k6/scenarios/executors/constant-arrival-rate/)、[丢弃迭代定义](https://grafana.com/docs/k6/latest/using-k6/metrics/reference/)、[固定版本发布](https://github.com/grafana/k6/releases/tag/v1.0.0)。本说明不要求使用托管云压测或新增外部账户。

## 开始前必须实测

两机均记录：时间/时区与时钟偏差、OS/kernel、CPU型号和可用核数、内存/交换、磁盘/文件系统、进程/容器资源限制、网卡/云带宽上限。被测机另记录PostgreSQL/pgvector、迁移、连接池、数据库内存参数、应用进程和worker数、B0提交及配置哈希。记录空接口往返分布及公网路径；云带宽配额与实际吞吐分别记录，未知写未验证。

每秒采样压测机总CPU、k6进程CPU、主机/进程内存；任一测量点发压端CPU或内存超过约70%，该点判无效，保留结果并降低发压压力或提升压测机后重测。不将丢弃请求/超时丢掉。

## 测量矩阵与判读

- 首期1万与10万条，真实文本的冻结模型真实向量；不使用随机/扰动向量。准备/向量化与压测分时，压测期间禁止真实模型调用，外部依赖用预计算向量与夹具。
- 负载含纯搜索、90%搜索+10%写入、70%搜索+30%写入及上下文接口；租户数10/100/1000与偏斜分布按原方案，查询按冻结中文语料长度分布。
- 每点预热1分钟、采样至少5分钟、重复3次。导入完成后更新统计信息，记录索引与后台清理状态；B0保持精确向量检索，不提前加近似索引或缓存优化。
- 分别报告客户端延迟与服务端处理耗时，统一写“跨公网压测，客户端延迟含网络往返”。客户端报告p50/p95/p99，服务端分查询向量化、通道召回、融合、取正文、序列化；不可用的阶段计时写未测，不以客户端时间冒充服务端。
- 带宽接近上限、两端CPU、数据库连接/IO/慢查询与排队联合归因；网络上限导致吞吐饱和只称网络受限，不当系统容量拐点。发压端饱和判无效。
- PF1–PF10与功能质量分开报告；任何尚未执行的指标值为未测，不填0。PF6近似索引对照等优化实验不在本次修改被测对象。

## 完成与释放

完成后归档私有逐请求结果、环境/资源日志、聚合报告与校验和；确认安全组/防火墙已关闭并撤销临时访问。只有完成这些检查，才明确通知负责人“压测机可释放”。当前压测未开始，尚不能作此声明。

脚本准备：`scripts/load/b0-open-loop.js`（开环预热与采样）、`scripts/b0-load-monitor.py`（每秒CPU/内存采样）。正式测点由统一调度器连续运行三次，传入只读私有请求集与短期令牌文件，保存每次原始指标；测点标记和资源采样窗口须按时间对齐。当前仅准备脚本，未安装临时机、未跑公网测点。
