# 逐字证据过滤方案与未通过的原型

适用范围：阶段1，冻结共同保留池的独立后处理实验。原始候选、模型标签、切分不覆盖。**当前原型未通过，不进入正式数据流水线。**

## 规则规范

1. 每个候选拆成独立主张，再检查主体、谓词/关系、实体/对象、程度、频率、数量、时间、诊断确定性。每项保留对应的用户原句、source_id、角色与原文片段。证据必须支持这个细节与这个关系的组合，不能在不同事件里拼字。
2. 候选有用户原话未出现的具体细节，一律不支持：例如增加“最”“轻度”“周末”“沙发”“被诊断”，或者把订婚月份附到结婚事件。缺细节即降级uncertain，**不自动修改成另一个较弱候选后称原候选正确**。
3. 只允许字形/标点/空白及明确的语法、亲属称谓等价归一化。不能删程度、频率、数量、时间、否定、条件或诊断；不能把一次活动变成长久偏好。归一化表在源码中明确列出，不使用开放式模糊相似度阈值代替证据。
4. 证据只能来自role=user的原始轮次。助手的名字称呼、职业介绍和建议不是用户自述；用户只有“嗯嗯”“对啊”而未本人复述具体细节时，当前严格证据规则不能当直接原话支持。第三人、引述、问句、假设、否定、不同时间事件不能混成肯定的本人事实。
5. 一个子句缺依据，就不能保留完整候选；保守降为uncertain供后续复核。这个后处理结论不是人工标签，不覆盖负责人已确认的keep/discard。

## 实现范围与失败

src/agent_memory/evals/verbatim_filter.py 保留严格顺序字符对齐原型，并实现细节片段原型：用户原话按陈述子句隔离，检查自身归属与偏好/身份谓词；具体限定词连续出现；所有非语法内容由用户原句中的连续片段覆盖。禁止仅按字袋拼接未知名词和从不同子句拼时间/事件。

**这些字符串检查只是必要条件，不能当完整语义蕴含证明。** 它对意译、指代、承前主语处理不足。具体误伤、剩余池与试验数字以脚本报告为准；当前错误召回高而误伤极高，不能判过滤方案通过。没有将词语白名单放宽到“恰好能凑够新盲审数量”。
